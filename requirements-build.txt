# What turns this tree into a wheel and an sdist, pinned by version and by
# hash in the same way as requirements.txt and refreshed by the same command.
#
#     pip install --require-hashes --requirement requirements-build.txt
#     python -m build --no-isolation
#
# pyproject.toml asks for `setuptools>=77`, which is right for anyone building
# from source: a floor, not a pin. But `python -m build` on its own resolves
# that range in a fresh environment from whatever the index serves that day,
# and would install an unverified setuptools to build the thing that is about
# to be published. --no-isolation makes it use the one installed from here.
#
# No twine. Its tree is some thirty packages, cryptography among them, to run
# a check that for a Markdown README comes down to the metadata being there.
# The build job in CI reads the wheel's metadata itself, and the publish
# action runs twine check with its own pinned copy before anything is
# uploaded.
